# Slotly — Submission Checklist

Версия: Slotly v1.0. **Status: Ready for submission.**
Проверено 2026-10-01 на Python 3.11.9.

## Основные требования

- [x] Владелец создаёт слоты с датой и временем через `/admin`.
- [x] Клиент видит расписание на выбранную дату и статусы «Свободно» / «Занято».
- [x] Свободный слот можно забронировать.
- [x] Сохраняются `client_name`, `client_contact`, `slot_id` и `created_at`;
  дата и время доступны через связанный `Slot`.
- [x] Отмена удаляет `Booking`, сохраняет `Slot` и освобождает его.
- [x] После отмены время можно забронировать повторно.
- [x] Двойное бронирование и одинаковые дата/время слота запрещены.
- [x] Пустые, пробельные и слишком длинные значения, неверная дата/время,
  неизвестные и занятые слоты, повторная отмена обработаны без неконтролируемых 500.
- [x] Используются FastAPI, SQLite, SQLAlchemy, Pydantic и Jinja2.
- [x] SQLite сохраняет данные между сессиями и запусками; foreign keys включены.
- [x] README содержит установку, запуск, тестирование и демонстрацию.

## Ограничения MVP

- `/admin` не имеет authentication и открыт как демо-интерфейс.
- Подтверждение и отмена доступны по числовому идентификатору записи;
  нет проверки владельца, пользовательских сессий и CSRF-защиты.
- Нет аккаунтов, нескольких организаций/услуг/сотрудников, переноса записей,
  уведомлений, оплаты и календарных интеграций.
- Дата и время не содержат timezone; будущая дата не обязательна.
- SQLite используется без распределённой инфраструктуры и миграций схемы.
- Это учебный MVP; ограничения не позволяют использовать его как защищённый
  сервис с реальными персональными данными в открытом доступе.
